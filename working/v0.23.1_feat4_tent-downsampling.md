# v0.23.1 Feature 23.1.4 — Tent (linear-splat) downsampling

Status: **done** (2026-11-06)

## Problem

v0.22 decimation kept every s-th sample, but the renderer places index i at
`i·L/dims` (periodic). With `dims = ceil(N/s)` and `N % s ≠ 0` the kept samples
really sit at `s·L/N` spacing → grid squeezed toward the origin + a seam at
the periodic wrap. For XSF "general grids" the decimated path also skipped
`trimRedundantPeriodicPlanes`, re-introducing the v0.22.1 endpoint bug.

## Change

- **`src/parsers/downsample.ts`** (new): `makeAxisMap` (periodic 1-D tent
  map, exact rational positions so `M = N` is a bit-exact identity),
  `TentAccumulator` (push samples in file order — `x-fastest` for XSF/CHGCAR,
  `z-fastest` for cube / C order; one Float64 row buffer + the Float32 output
  grid; separable normalization by per-axis weight sums), `tentDownsample`
  (in-memory wrapper), `detectRedundantEndpoints` (XSF closure planes from
  the first and last data planes only).
- **Byte paths** (`cubeParser`, `xsfParser`, `chgcarParser`): factor > 1
  feeds the accumulator; factor 1 writes straight through (unchanged
  output). XSF factor > 1 probes the first plane (after the grid header) and
  the last plane (before `END_DATAGRID_3D`) via new `lineIterator` helpers
  (`iterLineSpans`, `firstNumbers`, `lastNumbersBefore`), gives closure planes
  zero weight, and picks the factor on the trimmed dims.
- **String path** (`types.ts` `decimateVolumetric`): now `tentDownsample`.

## Pre-existing bugs found and fixed on the way

1. **String-path cap was a no-op for XSF / CHGCAR** (since v0.23): only
   `volumetric` was decimated and `attachGridList` then replaced it with the
   untouched `volumetrics[0]`. `matviz.volumetric.maxGridPoints` therefore did
   nothing for multi-grid-capable files under 256 MiB. New `decimateGrids()` in
   `index.ts` decimates every grid.
2. **Byte path dropped all grids but the first** (since v0.23):
   `parseStructureFileTrajFromBytes` passed only `volumetric` to
   `attachGridList`, so ≥ 256 MiB CHGCAR spin/SOC and multi-DATAGRID XSF lost
   magnetization / spin_up / spin_down / later datagrids. Now forwards
   `volumetrics`.

## Visual check / trade-off (R1)

`working/assets/v0.23.1_feat4_band15_iso_compare.png`: band15 iso 0.012,
2×2×1, full res vs old stride-3 vs new stride-3 tent. All lobes sit on the
atoms. The averaging lowers peak values, so at a fixed iso level the small
side lobes are visibly **smaller** in the tent version than at full res — the
expected low-pass cost of anti-aliasing (plan risk R1). If this matters more
than aliasing, swapping the splat for trilinear point interpolation keeps the
zero drift with less flattening; left as a user decision.
