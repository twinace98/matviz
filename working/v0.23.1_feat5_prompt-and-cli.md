# v0.23.1 Feature 23.1.5 — Resolution prompt + CLI parity

Status: **done** (2026-11-06). Implementation commit `bf95399`.

## Change

**Extension**
- New setting `matviz.volumetric.promptAboveBytes` (default 1 GiB, 0 =
  never). For files on the streaming path (local, ≥ 256 MiB) the header probe
  runs first; if the full-resolution grids need more than the limit, a
  QuickPick asks for the resolution before any grid data is read:
  `Recommended — 600×600×600 (0.80 GiB)`, `Smaller — 400×400×400`, and
  `Original` (full grid within the 4×10⁸-point safety cap) or `Larger`
  (largest grid within the cap) when that differs from the recommendation.
  Esc = Recommended. An explicit `matviz.volumetric.maxGridPoints` skips the
  prompt. Choice logic = pure `resolutionChoices()` in `volumetricProbe.ts`.

**CLI** (`scripts/render.ts`)
- Volumetric inputs (cube / XSF with a grid / CHGCAR; not `.axsf` or
  `ANIMSTEPS` animations) go through `probeVolumetric` +
  `parseVolumetricStream`; everything else keeps the string parser.
- `--max-grid-points <n|full>`, default **2×10⁷** (decision below). When the
  grid is downsampled, stderr prints
  `[matviz] grid 600×600×600 → 200×200×200 (factor 3, trilinear) …`.
- Grid handoff: raw Float32 side file (`<tmp>.f32`, removed afterwards)
  loaded in the page with XHR (fetch refuses `file://`); only written when
  `--iso` is set. Replaces `JSON.stringify(Array.from(grid))`, which hit the
  V8 string limit at ~300³.
- `--info` / `--json`: volumetric files are summarized from the header only
  (`readVolumetricStructure`); new `Grid:` / `Render grid:` lines and a
  `volumetric` JSON object (dims, periodic dims, grids in file / loaded,
  full-res bytes, factor, render dims / bytes).
- SKILL.md (option row, large-file recipe, troubleshooting) and README (CLI
  row, "Large files" bullet in Volumetric data) updated in the same change.

## Default CLI budget: 2×10⁷ (kept)

2.25 GiB cube (600³), 500×400 PNG, `--iso 0.5`:

| `--max-grid-points` | grid rendered | wall time |
|---|---|---|
| default 2e7 | 200³ (factor 3) | 19 s |
| 1e8 | 300³ (factor 2) | 23 s |
| full | 600³ | 67 s (needs `--timeout`) |

All three place the isosurface identically. A 1e8 default would allow grids
up to ~464³, which can exceed the default 30 s timeout; 2e7 keeps the
default command safe and `--info` tells the user the factor up front.
