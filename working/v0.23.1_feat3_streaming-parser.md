# v0.23.1 Feature 23.1.3 — Streaming volumetric parser

Status: **done** (2026-11-06). Implementation commit `69cb004`.

## Goal

User requirement 2: read the file in chunks and downsample while reading, so
memory ≈ the final grid regardless of the file size. Removes the 2 GiB
`fs.readFile` limit (v0.22 byte path) and the 512 MiB string limit.

## Change

- **`src/parsers/volumetricStream.ts`** (new, Node only — not imported by
  `parsers/index.ts`, so `fs` stays out of the webview/embed bundles):
  `parseVolumetricStream(filePath, filename?, { factor, maxGridPoints, probe,
  highWaterMark, onProgress, signal })`.
  - `probeVolumetric` → header bytes [0, dataOffset) parsed with the
    existing header parsers → `fs.createReadStream` (4 MiB chunks) from
    `dataOffset`.
  - Chunk scanner: **data mode** decodes tokens straight from bytes with
    `parseNumberToken` (Clinger fast path for ≤ 15 significant digits and
    |exp10| ≤ 22, otherwise `parseFloat` on the token → bit-identical to
    `parseFloat`); a letter-led token interrupts the grid. **Line mode**
    feeds per-format state machines that mirror the byte-path parsers (XSF
    multi-DATAGRID, CHGCAR blocks separated by augmentation sections, cube).
    Tokens / lines split across chunks are carried over.
  - Sinks: full-res store (factor 1) or `GridResampler` (factor > 1). XSF
    grid 0 uses the probe's closure flags; later grids with other dims judge
    their own first plane.
- `index.ts`: `finalizeVolumetricResult` (symmetry + named grid list) shared
  with the stream; a lone unnamed cube grid is named `density` like the
  string path.
- Exports for reuse: `parseCubeHeader`, `trimRedundantPeriodicPlanes`,
  `snapGridLatticeToCell`, `buildChgcarGrids`, `cellVolume`.
- **Extension** (`crystalEditorProvider.ts`): local (`file:`) volumetric
  files ≥ 256 MiB stream inside a cancellable progress notification
  ("x.xx / y.yy GiB"). Cancel → info toast, no fallback to the TextDocument
  path. Non-file schemes keep the `workspace.fs.readFile` byte path.

Deviation (logged in the impl spec): a blank line inside a CHGCAR grid block
no longer discards the partial grid; only text tokens interrupt. Malformed
files only.

## Verification

`node dist/test-volumetric-stream.js [--large]` — ALL PASS:

| check | result |
|---|---|
| `parseNumberToken` vs `parseFloat`: 35 edge tokens (signs, `.5`, `5.`, 16–20 digits, 1e±400, subnormal, `D` exponent, NaN/Infinity, malformed) + 200 000 random | 0 mismatches (`Object.is`) |
| factor 1 vs string path: 6 fixtures + 6 synthetic files (cube, XSF closure / no closure / two grids, CHGCAR spin / SOC) | bit-identical data, names, dims, structure, space group |
| factor 2 / 3 vs byte path | identical dims + stride, values ≤ 1e-6 rel |
| chunk sizes 7 B, 13 B, 1 KiB vs 4 MiB | bit-identical |
| progress callback | monotonic, ends at file size |
| abort | rejects with `AbortError` |

`--large` (real 2.25 GiB cube, 600³):

| check | result |
|---|---|
| `fs.readFile` (v0.22 byte path) | `ERR_FS_FILE_TOO_LARGE` |
| stream at factor 2 | 300³ in **16 s (143 MiB/s)** |
| peak RSS growth (VmHWM, clean child process) | **+194 MiB** for a 103 MiB output grid |
| blob peak position | (0.400, 0.500, 0.600) as written |

Memory overhead beyond the output grid is constant (~90 MiB: in-flight read
chunks + not-yet-collected chunk buffers), not proportional to the file:

| file | path | time | peak RSS growth |
|---|---|---|---|
| 313 MB cube → 150³ | stream | 3.4 s | +103 MiB (13 MiB grid) |
| 313 MB cube → 150³ | byte path (v0.22) | 5.3 s | +598 MiB |
| 2.25 GiB cube → 300³ | stream | 16 s | +194 MiB (103 MiB grid) |
| 2.25 GiB cube | byte path (v0.22) | — | refused (> 2 GiB) |

Regression: all other `dist/test-*.js`, `test-byte-volumetric`, visual
11/11, `tsc` clean. `fs`/`createReadStream` only in `dist/extension.js`.
