# v0.23.1 Feature 23.1.4 — Drift-free downsampling (periodic trilinear)

Status: **done** (2026-11-06)

## Problem

v0.22 decimation kept every s-th sample, but the renderer places index i at
`i·L/dims` (periodic). With `dims = ceil(N/s)` and `N % s ≠ 0` the kept samples
really sit at `s·L/N` spacing → grid squeezed toward the origin + a seam at
the periodic wrap. For XSF "general grids" the decimated path also skipped
`trimRedundantPeriodicPlanes`, re-introducing the v0.22.1 endpoint bug.

## Decision: trilinear interpolation, not tent averaging

Implemented first as planned (tent / linear-splat average, commit
`f5f2377`). The band15 iso comparison showed the averaging visibly shrinks
small lobes at a fixed iso level. **User chose trilinear interpolation**
(2026-11-06): output nodes take the linear interpolation of the source at
their exact periodic positions → no drift, peaks largely kept; the trade-off
is that features narrower than one output voxel can alias.

`working/assets/v0.23.1_feat4_band15_iso_compare.png` — band15, iso 0.012,
2×2×1, two views: full res / v0.23.0 point sampling / tent / trilinear (s=3).

## Change

- **`src/parsers/downsample.ts`** (new):
  - `makeAxisMap(N, M, skipLast)`: node j at source coordinate
    `x = j·N_eff/M` (exact rational → M = N_eff is a bit-exact identity and
    N % s = 0 equals point sampling), reading floor(x) and floor(x)+1
    mod N_eff with weights 1−t, t. Stored transposed: each source index feeds
    ≤ 2 adjacent output nodes (M ≤ N_eff).
  - `GridResampler`: push samples in file order (`x-fastest` for
    XSF/CHGCAR, `z-fastest` for cube / C order); one Float64 row buffer + the
    Float32 output grid; separable normalization. No plane buffers needed.
  - `resampleGrid` (in-memory wrapper), `detectRedundantEndpoints` (XSF
    closure planes from the first and last data planes only).
- **Byte paths** (`cubeParser`, `xsfParser`, `chgcarParser`): factor > 1
  feeds the resampler; factor 1 writes straight through (unchanged output).
  XSF factor > 1 probes the first plane (after the grid header) and the last
  plane (before `END_DATAGRID_3D`) via new `lineIterator` helpers
  (`iterLineSpans`, `firstNumbers`, `lastNumbersBefore`), never reads closure
  samples, and picks the factor on the trimmed dims.
- **String path** (`types.ts` `decimateVolumetric`): now `resampleGrid`.

## Pre-existing bugs found and fixed on the way

1. **String-path cap was a no-op for XSF / CHGCAR** (since v0.23): only
   `volumetric` was decimated and `attachGridList` then replaced it with the
   untouched `volumetrics[0]`. `matviz.volumetric.maxGridPoints` therefore did
   nothing for multi-grid-capable files under 256 MiB. New `decimateGrids()` in
   `index.ts` decimates every grid.
2. **Byte path dropped all grids but the first** (since v0.23):
   `parseStructureFileTrajFromBytes` passed only `volumetric` to
   `attachGridList`, so ≥ 256 MiB CHGCAR spin/SOC and multi-DATAGRID XSF lost
   magnetization / spin_up / spin_down / later datagrids. Now forwards
   `volumetrics`.

## Follow-up: "v0.23.0 looks closest in the image" (2026-11-06)

User remark on the comparison image. Quantified instead of eyeballed: each
downsampled grid is evaluated at the full-res sample positions exactly as the
renderer places it (`j·L/M`, periodic trilinear — what marching cubes draws)
and compared with the full-res grid at the same iso. J = Jaccard overlap of
the iso-enclosed regions (position + size), vol = enclosed-volume ratio.

| case | s | v0.23.0 point | tent | **trilinear** | divisor-stride point |
|---|---|---|---|---|---|
| band15, iso 0.012 | 2 | J .570 vol .821 | J .889 vol .889 | **J .935 vol .940** | J .935 (st 2) |
| band15, iso 0.012 | 3 | J .546 vol .730 | J .645 vol .645 | **J .809 vol .809** | J .674 (st 4) |
| LiF polaron, iso 0.3·max | 2 | J .550 vol .550 | J .250 | **J .550 vol .550** | J .550 |
| LiF polaron, iso 0.3·max | 3 | **J .213 vol .425** | J .000 | J .025 vol .025 | J .000 (st 4) |
| blob 100³ σ .05 | 3 | J .615 vol .855 | J .828 | **J .894 vol .894** | J .823 |
| blob 101³ σ .05 | 2 | J .788 vol .892 | J .877 | **J .923 vol .923** | (prime: no downsample) |

Why v0.23.0 *looks* closest in the band15 picture: it shows raw sample
values (no interpolation, so lobes keep their size) and its error is a ~5 %
compression of positions toward the origin, which is hard to see at that
zoom. Its J is the lowest because the lobes are displaced.

The one case it wins (LiF polaron, s = 3) is sampling-phase luck: shifting
the point-sampling start by 1 or 2 source voxels gives J .213 → .056 → .000
and vol .425 → .425 → .000 (band15: J .546 → .340 → .191). A feature
narrower than one output voxel cannot be represented reliably by any of the
four methods; trilinear loses its peak deterministically, point sampling
keeps or loses it at random. Mitigation belongs in 23.1.5 (the resolution
prompt), not in the resampler.
