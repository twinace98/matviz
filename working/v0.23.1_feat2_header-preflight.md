# v0.23.1 Feature 23.1.2 — Header-only volumetric preflight

Status: **done** (2026-11-06)

## Goal

User requirement 1: see the grid size and decide the downsampling **before**
the grid data is read.

## Change

- **`src/parsers/volumetricProbe.ts`** (new, Node `fs` only — not bundled
  into the webview/embed):
  - `probeVolumetric(filePath, filename?, { maxGridPoints, maxHeaderBytes,
    maxPlaneBytes })` → `VolumetricProbe`: `format`, `fileSize`, `dims` (as
    written), `effectiveDims` (XSF closure planes dropped), `gridCount`
    (exact for cube; estimated from file size ÷ (bytes-per-value × N) for
    XSF / CHGCAR, CHGCAR snapped to 1 / 2 / 4), `outputGridCount` (CHGCAR
    ISPIN=2 → 4 loaded grids), `fullResBytes`, `recommendedFactor` +
    `recommendedDims` for the point budget, `redundantEndpoint` +
    `endpointSource`, `dataOffset`, `bytesPerValue`, `bytesRead`.
  - `dimsForFactor`, `bytesForFactor` helpers (for the 23.1.5 prompt).
  - Head read in 256 KiB doubling steps until the grid header parses (cap
    16 MiB); a trailing partial line is ignored unless at EOF, so a read
    boundary cannot truncate the dims line. XSF: first data plane from the
    head, last plane before the final `END_DATAGRID_3D` via a positioned
    tail read (single-grid files only), each ≤ 64 MiB of text.
- **`detectRedundantEndpointsDetailed`** (`downsample.ts`): per-axis verdict
  equal / differ / **inconclusive**. Near-zero boundaries (≤ 1e-3 × max)
  always "match", so they no longer vote; inconclusive axes follow the
  majority of conclusive axes (writers apply the closure convention to all
  axes), tie → no closure, all inconclusive → XSF spec default (closure).
  `lastPlane = null` makes z inconclusive (multi-grid XSF: the file tail
  belongs to another grid). The byte-path XSF downsampler uses the same
  function, so it gets the fix too.
- `findPoscarEnd` exported from `chgcarParser.ts` so the probe and the parser
  read the CHGCAR header identically.
- `scripts/lib/synthGrids.ts` (new): synthetic cube / XSF (closure, no
  closure, multi-grid) / CHGCAR (ISPIN 1, 2, SOC) generators, shared with
  the 23.1.3 streaming tests.

## Found while testing

The first version judged closure per axis on the first plane alone and
reported a **false closure** on a no-closure XSF whose y boundaries were
~1e-5 of the max (Gaussian far from the boundary) — the typical situation for
the large-box files this feature targets. Fixed by the inconclusive-axis
rule above. A second failure (two-grid XSF: last plane belongs to grid 2 and
out-voted x) fixed by not reading the tail for multi-grid files.
