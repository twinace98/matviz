# v0.23.1 Feature 23.1.1 — CLI white-image fix

Status: **done** (2026-11-06)

## Problem

Users reported the CLI (`node dist/render.js`) often writes an all-white PNG.
Root causes reproduced in `scripts/render.ts`:

1. **Fixed fog** `FogExp2(bg, 0.015)` while the camera distance is
   `d = 2.6 × size`. Center fog = `1 − exp(−(0.015·d)²)`: 5 % at 5.6 Å, 46 % at
   20 Å, 91 % at 40 Å, ~100 % ≥ 60 Å. Fog color = background, so on `--bg white`
   a large structure becomes an all-white image (NaCl 10×10×10, crambin.pdb).
   The webview already scaled fog by scene size; the CLI never got the port.
2. **Fixed clipping range** (ortho `near −500 / far 500`, persp `far 500`):
   structures over ~160 Å were clipped entirely (250 Å cell → 0 non-background
   pixels, even with fog disabled).

Also fixed while here:

3. **Shared temp page** `dist/_render_tmp.html`: concurrent runs could
   overwrite or delete each other's page. Not reproduced in 8-way parallel
   runs (timing window is small) but a real code-level race.
4. **Hard-coded 30 s deadline + `networkidle0`**: very large scenes fail with
   `Navigation timeout of 30000 ms exceeded`.

Not a bug, documented instead: `--bg transparent` writes alpha-0 PNGs that
look white in white-canvas viewers.

## Change (`scripts/render.ts`)

- After camera placement (and `--rotate`):
  `camDist = |camera − center|`; `camera.far = max(500, camDist + 2·size)`;
  ortho `near = −far`; fog density `min(0.015, 0.3 / camDist)` (center fog
  capped at ≈ 8.6 %; unchanged for camDist < 20 Å). Clipping update applies
  to `--bg transparent` too.
- Temp page → `os.tmpdir()/matviz_render_<pid>_<ms>.html`.
- `--timeout <s>` (default 30, validated > 0) for `goto` and
  `waitForFunction`; `goto` waits for `domcontentloaded` (`__renderDone` is
  the completion signal).
- SKILL.md: `--timeout` row, white-image + transparent + timeout
  troubleshooting. README: `--timeout` row.
