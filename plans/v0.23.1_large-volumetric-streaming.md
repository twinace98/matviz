# v0.23.1 — Large volumetric streaming + artifact-free downsampling + CLI fixes

> Maintenance patch inserted ahead of v0.24 (roadmap numbers v0.24–v0.26
> unchanged). Kicked off 2026-11-06 after a CLI bug report ("CLI often
> writes an all-white PNG") and a review of v0.22's large-file limits.

## Goal

1. Let the user **see the grid size and decide the downsampling before the
   data is read** (header-only preflight).
2. **Stream** volumetric files in chunks and downsample during ingestion, so
   peak memory ≈ the *output* grid, independent of the on-disk file size.
3. Downsampling must **not break the isosurface**: no position drift, no PBC
   seam, regardless of whether `N` is divisible by the factor.
4. Fix the CLI white-image bug and bring the CLI onto the same large-file path.

## Why now — findings from the 2026-11-06 investigation

All measured in a headless session (Node v22.23.4, 15 GB RAM).

- **CLI white image**: `scripts/render.ts` uses a fixed `FogExp2(bg, 0.015)`
  while the camera distance scales with structure size (`d = 2.6·size`).
  Fog at the center: 5 % for 5.6 Å, 46 % for 20 Å, 91 % for 40 Å, ~100 %
  ≥ 60 Å. Since fog color = background, a large structure on `--bg white`
  renders all white (reproduced: NaCl 10×10×10, crambin.pdb). The webview
  already scales fog (`renderer.ts:2842`); the CLI never got that port.
- **CLI clipping**: fixed `near=-500 / far=500` (ortho) and `far=500`
  (persp) clip every object for structures over ~160 Å (reproduced: 250 Å
  cell → 0 % non-background pixels even without fog).
- **CLI large grids**: grid is JSON-inlined into HTML. 100³ (12 MB) 8 s,
  200³ (93 MB) 22 s (near the 30 s navigation timeout), 300³ (313 MB) →
  `RangeError: Invalid string length` at `JSON.stringify`. The input is also
  read with `readFileSync(…,'utf-8')` (512 MiB string ceiling).
- **Extension 2 GiB wall**: the v0.22 byte path does
  `vscode.workspace.fs.readFile` of the whole file. Node's `fs.readFile`
  rejects files > 2 GiB (`ERR_FS_FILE_TOO_LARGE`, measured). STATUS's
  "opens up to 4 GiB" was never tested (largest test was 297 MiB).
- **Downsampling drift**: current stride decimation keeps every s-th sample
  but the renderer maps index→position with `step = L / ceil(N/s)`. When
  `N % s ≠ 0` the grid is squeezed. Measured |ρ|-weighted centroid shift
  vs full resolution: blob 100³ s=3 **1.70 voxel**, blob 101³ s=2
  **0.86 voxel**, `band15_Gamma.xsf` s=3 **1.34 voxel** (decimation also
  skips `trimRedundantPeriodicPlanes`, re-introducing the v0.22.1 bug),
  LiF s=3 0.63 voxel. Divisible cases (100³ s=2) are exact.
- **WASM is not a limit**: moyo-wasm only receives atoms; the webview loads
  no WASM. Not touched by this version.

## Out of scope

- Binary formats (HDF5 / NetCDF / BerkeleyGW `.h5`).
- Web-worker offload of marching cubes in the webview.
- Out-of-core / brick rendering.
- Changing marching-cubes or iso-level semantics.

## Risks / decision gates

- **G1 (VSCode TextDocument)**: `CustomTextEditorProvider` makes VSCode
  load the file as a `TextDocument` *before* our code runs. Whether VSCode
  can open a > 2 GB text model was never tested. **Gate**: manual check in
  VSCode with the 2.5 GB synthetic cube. If VSCode refuses or hangs, a
  separate `CustomReadonlyEditorProvider` for oversized volumetric files is
  needed — that is plan drift and comes back to the user before any work.
- **R1 (peak flattening)**: tent averaging lowers sharp maxima (core
  charge spikes). Iso levels picked as a fraction of the max shift slightly.
  The info pill already labels downsampled loads; document it.
- **R2 (XSF endpoint probe)**: streaming cannot see the whole grid before
  splatting, so the redundant-plane test runs on the first plane (x, y)
  and on first vs last plane (z) read by positioned reads. Factor-1 loads
  keep the existing full-volume `trimRedundantPeriodicPlanes` exactly.
- **R3 (CLI fog change)**: structures larger than ~7.7 Å change slightly
  (lighter fog), e.g. `graphene.xsf`, `buckyball.xyz`. Visual baselines
  (`npm run test:visual`) for affected fixtures will be re-blessed.
