## 23.1.4 Tent downsampling (`src/parsers/downsample.ts`, new)

Pure, format-agnostic, streaming-friendly.

```ts
export interface AxisMap { N: number; M: number; Neff: number; j0: Int32Array; t: Float32Array; }
export function makeAxisMap(N: number, M: number, skipLast: boolean): AxisMap;
export class TentAccumulator {
  constructor(nx, ny, nz /*source, file order agnostic*/, mx, my, mz, opts: { skip: [bool,bool,bool]; order: 'x-fastest' | 'z-fastest' });
  pushValue(v: number): void;   // called once per source sample in file order
  finish(): Float32Array;       // C-order [mx][my][mz], normalized
}
```

- Periodic mapping per axis: `x = i·M/Neff`, `j0 = floor(x)`, `t = x − j0`,
  weights `(1−t) → j0`, `t → (j0+1) mod M`. `Neff = N − 1` with index
  `N−1` given zero weight when `skipLast` (XSF redundant endpoint).
- Separable normalization: per-axis weight sums `Wx[j]` computed in
  `makeAxisMap`; final value = `acc / (Wx·Wy·Wz)`. No 3-D weight array.
- Row buffering: samples along the file-fastest axis accumulate into a
  length-`M_fast` Float64 row (2 adds/sample). At row end the row is
  splatted into ≤ 4 output rows (mid × slow weights). Output buffer is the
  only O(M³) allocation (Float32).
- `M = ceil(Neff / s)` with `s` from `chooseStride` (kept so the UI's
  "stride s" wording and `maxGridPoints` semantics stay). Factor 1 →
  `t ≡ 0`, identity; callers bypass the accumulator entirely at factor 1.
- Replace `decimateVolumetric` (string path) with an in-memory call into the
  same accumulator so both paths share one algorithm.

Unit test `scripts/test-downsample.ts`: identity at factor 1; constant field
stays constant; mean preserved; centroid shift ≤ 0.10 output voxel on a
periodic Gaussian for N ∈ {100, 101, 64, 41} × s ∈ {2, 3}; skipLast grid
equals the trimmed grid's result.

## 23.1.2 Header preflight (`src/parsers/volumetricProbe.ts`, new)

```ts
export interface VolumetricProbe {
  format: 'cube' | 'xsf' | 'chgcar';
  fileSize: number;
  dims: [number, number, number];
  gridCount: number | null;      // CHGCAR: from ISPIN guess via file size; XSF: null until streamed
  fullResBytes: number;          // dims product × 4 × max(gridCount,1)
  recommendedFactor: number;     // chooseStride vs maxGridPoints / safety cap
  redundantEndpoint?: [boolean, boolean, boolean];  // XSF only
}
export async function probeVolumetric(filePath: string, opts?): Promise<VolumetricProbe>;
```

- Read head with `fs.promises.open` + `read` in 256 KiB steps until the
  dims line is found (XSF: after `BEGIN_DATAGRID_3D` + label; cube: line 4–6;
  CHGCAR: first blank line after positions). Hard cap 16 MiB of header.
- XSF endpoint test (only needed when factor > 1): first plane values from
  the head (x and y axes: compare `i=0` vs `i=N−1` rows/columns), last plane
  from a positioned tail read before `END_DATAGRID_3D` (z axis: first vs
  last plane). Tolerance as in `trimRedundantPeriodicPlanes`
  (`1e-5 · maxAbs` of the sampled values). Planes > 64 MiB of text → fall
  back to the XSF-spec default (general grid ⇒ endpoint present).
- Pure Node (`fs`), usable from extension host and CLI.

## 23.1.3 Streaming parser (`src/parsers/volumetricStream.ts`, new)

```ts
export async function parseVolumetricStream(
  filePath: string, filename: string, opts: { factor: number; probe: VolumetricProbe },
): Promise<ParseTrajectoryResult>;
```

- `fs.createReadStream(filePath, { highWaterMark: 4 << 20 })`. Each chunk is
  scanned byte-wise; the partial trailing line is carried into the next
  chunk (copy ≤ one line). No full-file Buffer/string ever exists.
- Header section (atoms etc.) is collected as text up to the dims line and
  handed to the existing header parsers (`parseCubeHeader`, `parseXsf`,
  POSCAR part of CHGCAR) — no new structure parsing.
- Data section: allocation-free float scanner over the byte chunk
  (sign / digits / `.` / `e|E|d|D` exponent), feeding
  `TentAccumulator.pushValue` (factor > 1) or writing straight into the
  output Float32Array (factor 1).
- State machines mirror the current byte-path parsers: cube (z-fastest,
  single grid), XSF (x-fastest, multi `BEGIN_DATAGRID_3D` with labels),
  CHGCAR (x-fastest, multiple blocks separated by `augmentation` sections +
  repeated dims line → `buildChgcarGrids`).
- Factor 1: then apply `trimRedundantPeriodicPlanes` / `snapGridLatticeToCell`
  exactly as today → bit-equality with the string path.
- Extension host: used when `document.uri.scheme === 'file'` and size ≥
  `RAW_BYTE_THRESHOLD` (256 MiB). Non-file schemes keep the
  `workspace.fs.readFile` byte path (≤ 2 GiB).
- Progress: `vscode.window.withProgress` (notification, cancellable) fed by
  bytes read / file size.

Test `scripts/test-volumetric-stream.ts`: stream vs string path bit-equal on
h2o.cube, LiF, band15, xsf-two-datagrid, both CHGCAR fixtures; chunk-size
fuzz (highWaterMark 1 KiB, 7 B, 4 MiB) gives identical output; 2.5 GB
synthetic cube RSS delta check.

## 23.1.5 Decision UX + CLI parity

Extension (`src/editor/crystalEditorProvider.ts`, `package.json`):
- New setting `matviz.volumetric.promptAboveBytes` (number, default
  `1073741824`, `0` = never prompt).
- Flow: stat → `probeVolumetric` → if `fullResBytes > promptAboveBytes`:
  QuickPick items `Recommended — 600³ (0.86 GB)`, `Smaller — 400³`,
  `Original — 1200³ (6.9 GB)`; Original disabled/hidden when it exceeds the
  safety cap. Esc = Recommended. If `maxGridPoints` is set, it wins and no
  prompt is shown.
- Info pill wording unchanged ("iso: 1200³ → 600³ (stride 2)"), plus
  "tent-averaged" tooltip.

CLI (`scripts/render.ts`):
- Volumetric inputs go through `probeVolumetric` + `parseVolumetricStream`
  (no `readFileSync` of the whole file).
- `--max-grid-points <n>` (default: safety cap 4e8 — but a CLI-specific
  default of 5e7 is proposed to stay inside SwiftShader time budgets;
  decided during impl, logged).
- `--info` adds `Grid: 1200×1200×1200 (6.9 GB at full res), recommended
  factor 2 → 600³`. JSON adds a `volumetric` object.
- Grid handoff: write `Float32Array` bytes to a temp `.f32` file next to the
  temp HTML; page does `fetch(file://…)` → `arrayBuffer()` →
  `new Float32Array`. JSON carries only origin/lattice/dims.
